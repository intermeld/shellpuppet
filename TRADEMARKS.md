# Trademark policy

ShellPuppet and Intermeld are trademarks of Red Eagle Tech Ltd, as are the
ShellPuppet and Intermeld logos. UK trade mark applications for both names are
pending. This policy says how you can use the names, and it exists for one
reason: so that anyone who sees the ShellPuppet name knows they're getting
ShellPuppet.

The software is licensed under [Apache-2.0](LICENSE), and that licence
deliberately grants no trademark rights (section 6). The code is free to use,
change and redistribute; the names tell people whose code it is.

## You don't need to ask

- **Referring to ShellPuppet or Intermeld truthfully**: reviews, articles,
  talks, comparisons, tutorials and documentation.
- **Saying your product works with, connects to or is built on ShellPuppet**,
  as long as it's true and you don't suggest we made or endorse your product.
  "Works with ShellPuppet" is fine; "ShellPuppet for Kubernetes" as your
  product's name is not.
- **Redistributing unmodified ShellPuppet under its own name**, including in
  package repositories and operating-system distributions, as long as it's the
  unmodified release.
- **Descriptive use in your own repository, package and plugin names** where
  the reference is a description (`shellpuppet-plugin-example`) rather than a
  claim to be ShellPuppet, and in community spaces, user groups and teaching.

## Please ask first

Write to legal@redeagle.tech before:

- using the names or logos in your own product, service, company, domain or
  social-media account name;
- using the logos for anything other than linking to or referring to the
  project;
- using the names in a way that suggests sponsorship, partnership or
  endorsement by Red Eagle Tech;
- any commercial use of the names beyond truthful reference.

## Modified versions and forks

You may modify ShellPuppet and distribute your changes; that's the licence at
work. If you distribute a modified version to other people, give it your own
name. You can say it's "based on ShellPuppet" or "a fork of ShellPuppet", and
you must keep the licence and notice files, but the modified thing shouldn't
be called ShellPuppet, because it isn't the thing we release and test. The
same applies to hosted services built on modified code.

Contributing changes back through this repository is different: a pull request
is a change to ShellPuppet, not a modified version of it.
